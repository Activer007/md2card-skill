## 第一、二期执行顺序（历史）

1. 固定输入契约与回归测试，先保证旧 Markdown 可用。
2. 添加诊断、资源上限、结构化错误与可追溯 manifest。
3. 抽离布局，接入本地图片与品牌，不引入任意 HTML/CSS。

5. CI 必须具备 Chromium、中文字体、pdfinfo、pdftotext；实际导出八版式 × 五主题，检查失败路径。
6. 查看真实输出，修复发现的问题；将选定 PNG 作为 README 展示图片，记录对应源命令和提交。

## 第三期范围与行为契约

本期已完成下述源码、CI 与限定范围的视觉验收，保持独立草稿 PR，尚未合并。目标是保留原文的受限自动分页，不是自动写作或全版式排版引擎。

- 默认 `--paginate manual`，保留显式分卡、八版式和现有元数据行为。`--paginate auto` 为主动选择，不默默增加卡片。
- 自动模式仅接收 `explainer`、`steps`，卡片元数据仅允许 `layout`。其余版式或字段以 `PAGINATION_UNSUPPORTED_LAYOUT` / `PAGINATION_UNSUPPORTED_METADATA` 明确拒绝，不丢弃来源、说明或其他字段。
- `===` 是不可跨越的锁定边界。仅在各显式分段内部继续拆分，保留 token、文本、顺序和来源。
- 段落、代码、引用、图片及含嵌套列表的顶层列表项不可拆分；有序列表续页保留编号；表格只按行拆分，重复表头明确记录来源；连续标题与后续内容单元保持在一起。
- 通过真实 Chromium 的屏幕和打印测量进行有界贪心分页。先用 `200/200` 页脚探测，再以实际页数对最终全套卡片重新检查。
- 候选组放不下时整组移至下一张，只允许一次空白卡片尝试；仍溢出则 `PAGINATION_ATOMIC_OVERFLOW`、退出码 2，并给出源位置，不生成裁切产物。预算或覆盖异常分别为 `PAGINATION_BUDGET`、`PAGINATION_COVERAGE`，退出码 1。
- 上限为 2,000 个语义单元、4,000 次候选探测、200 个显式分段或输出卡片，以及 10,000 条引用定义或来源记账区间；超限明确拒绝，不截断。沿用资源、像素、产物和时间预算，最终 manifest 记录分页模式与结构化来源、覆盖和重复表头信息。
- Skill 可解释失败并提出修改建议，但只有取得用户对内容编辑的许可才修改原文。渲染器无内置模型调用、缩字或自动改写。

### 测试分层与发布门槛

1. 先运行非浏览器测试，覆盖源位置、覆盖守恒、语义分组、错误码与手动模式回归。可控测量函数或假浏览器只验证算法和生命周期，不能证明真实排版成功。
2. 在允许启动 Chromium 的 CI 环境运行真实 screen/print 测量与 HTML、PNG、原生文本 PDF 导出；检查最终精确页数和 PDF 可检索文本。记录精确提交、CI 链接、通过/失败/跳过数，不能只写“测试通过”。
3. 针对长段落、长代码、引用、带嵌套列表的大列表项、过高图片和表格行，确认不能完整放入空白卡片时返回可定位的失败，而不是裁切或擅自拆开。
4. 交叉检查原始来源、语义单元和最终卡片。确认无丢失、无乱序，只有记录在案的表头重复；确认所有显式边界、有序列表续号和标题关系保持。
5. 对新增自动分页案例查看实际联系表及每张原尺寸导出，检查中文缺字、标题孤立、代码缩进、表格续页、页脚碰撞、过量空白和阅读节奏。几何无溢出不等于视觉验收。
6. 独立代码审查后修复缺陷，重新运行受影响测试。只有新提交的 CI、实际产物检查与视觉范围分别有证据，才更新对应状态为完成；本地被禁止的浏览器测试继续标记为受限。
