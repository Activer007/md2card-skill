## 执行顺序

1. 固定输入契约与回归测试，先保证旧 Markdown 可用。
2. 添加诊断、资源上限、结构化错误与可追溯 manifest。
3. 抽离布局，接入本地图片与品牌，不引入任意 HTML/CSS。
4. 增加预览、联系表与三套原创示例。
5. CI 必须具备 Chromium、中文字体、pdfinfo、pdftotext；实际导出八版式 × 五主题，检查失败路径。
6. 查看真实输出，修复发现的问题；将选定 PNG 作为 README 展示图片，记录对应源命令和提交。

## 后续阶段（仅规划，未实现）

- 第三期候选：基于实际浏览器测量的语义分页。先保持标题与后续段落、列表项、表格行、引用和代码块的语义边界，再测量是否放得下；必须保留显式分页优先级、原文和可追溯源位置。仅作为后续候选，本轮没有实现自动分页，也不会自动改写内容。
- 其他候选：更多内容模板、批量工作流与更细粒度可访问性检查。实施顺序需依据实际使用反馈另行确定。
- 不默认扩展到自动分页、AI 改写、账号、云同步、内置模型或 PPTX；需要单独确定范围和验收标准。
