# 真实静态模板图库（M9 / LIB-03）

打开 [离线图库](gallery/index.html) 查看已验收的真实 PNG 与单独的待验收源码目录。
此切片不包含系列配方、多画幅设计、部署、在线渲染或新的模板视觉验收。

## 生成与来源

```bash
node scripts/build-template-gallery.mjs
node scripts/build-template-gallery.mjs --check
node --test tests/template-gallery.test.mjs
```

也可使用 `npm run gallery:build`、`npm run gallery:check`、`npm run test:gallery`。
这些命令仅使用 Node.js 内置模块与模板注册表，不导入渲染器、不启动浏览器、
不请求网络，不需要安装浏览器。`--check` 验证签入的静态索引与当前输入一致。
修改注册表、证据绑定、示例或生成器后需重新生成索引。

唯一模板集合来自 [scripts/templates.mjs](../scripts/templates.mjs)。家族、用途、
图片需求、示例密度、内容结构、限制、版本、来源和输入路径均从该注册表读取；
不另维护一份模板清单。家族的中文显示名只是标签映射，不构成另一个模板集合。

[证据绑定](template-gallery-evidence.json) 记录已验收批次的文档、机器来源文件与
验收范围，并固定验收文档与来源文件的 SHA-256。更新证据后应先复核，再更新绑定，不能自动刷新来绕过失败。当前 `visual-m1` 的范围转录自 [原验收记录](TEMPLATE_ACCEPTANCE.md)：
v1、standard、portrait 1080×1440、manual。历史来源 JSON 中的
`mobileAudit[].status` 是自动采集时的 `rendered-not-visually-reviewed`，
最终独立逐图结论在验收文档；图库不修改或重新解释原始机器记录。

构建会拒绝：

- 缺失、重复、孤立的验收记录，未知验收批次或不匹配的注册状态。
- 已验收模板的版本、密度、画幅与该批验收范围不一致。
- 示例路径不匹配模板 ID，或示例元数据中的模板 / 密度与注册表不一致。
- 真实 PNG、输入、验收文档或来源文件缺失；PNG / 输入 / 证据文件 SHA-256 不符。
- PNG 签名、IHDR 尺寸或来源提交 / 树 / 产物哈希格式不符。
- 验收文档不含对应批次、精确提交、真实 PNG 和原始输入链接。
- 不安全路径、逃逸仓库的符号链接、非普通文件、失效的图库资源。

SHA-256 是完整性校验，不是自动生成的视觉判断或来源真实性背书。
新验收批次必须先有独立逐图复核证据，再明确添加绑定；生成器绝不自动“验收”模板。
当前严格范围只允许已有 M1 规格，新画幅或新版验收需要单独评审并扩展契约。

## 界面与筛选语义

- 已验收、源码已实现、待验收与家族数分别计数；待验收数等于已实现减去已验收。
  这些数字由注册表生成，新增条目后重新生成；不把配色或画幅计为模板。
  当前仅 T01 / T05 / T17 / T25 有视觉验收证据，新增源码候选不能扩大已验收数。
- 真实预览直接引用仓库保存的原始 PNG，按原比例显示，不另造概念图、色板、
  CSS 缩略图或占位截图。只有 T01 / T05 / T17 / T25 有预览。
- 候选目录只有文字契约与示例链接，没有图片占位；与成品区域明显分开。
- 家族、图片需求、注册示例密度是精确筛选；用途输入按 ID、名称、用途做
  NFKC 规范化后的不区分大小写子串匹配，各条件取交集，不把用户输入当正则。
- “注册示例密度”不等于所有支持密度都已验收。目前全部注册示例为 standard，
  选择 compact / editorial 得到空结果是诚实的范围说明，不套用 standard 截图。
  三种密度在渲染器中仅改变间距，不能用于宣称其他密度的视觉质量。
- 筛选状态只在当前页面内存中，不保存、不发出请求、不修改链接或输入文件。
  计数同时报告已验收 / 待验收命中数；重置清空所有条件。
- 无脚本时所有条目、完整输入、PNG、证据链接和原生 details 详情仍可访问。
  脚本正常初始化后才显示筛选器，脚本失败不会留下不能操作的控件。

使用完整仓库离线打开 `docs/gallery/index.html`，不要仅复制 HTML。
也可在允许的环境用现有本地静态服务器浏览，无需第三方托管或 CDN。
脚本是本地经典脚本，不用可能在 file:// 下触发模块 CORS 的模块加载或 fetch。
各浏览器对 file:// 与 CSP 的具体行为仍需真实浏览器验证，不能以源码测试代替。

## 安全与可访问性边界

图库有独立 CSP：默认全部拒绝，只允许本地同源脚本、样式、图片；
网络连接、字体加载、表单提交、嵌入对象和 base URL 均被禁止。
无内联脚本/样式、事件处理器、外部资源、用户 HTML、eval 或 DOM HTML 注入。
模板字段在生成 HTML 的文本和属性位置都转义；路径有独立白名单与真实路径检查。
筛选只读 dataset，通过 `hidden` 和 `textContent` 更新界面。
此策略不改变卡片渲染器、导出 HTML、预览或联系表的 CSP。

源代码包含原生 label / select / input / button / details、跳过导航、可见焦点、
礼貌实时计数、空状态、语义标题和无裁切 PNG。布局有窄屏断点与强制颜色支持。
这些是可检查的实现意图，**不是已完成的键盘、读屏、对比度或手机视觉验收**。

## 为未来获准环境准备的真实 Chromium 检查

本切片另提供 `scripts/validate-gallery.mjs`。它与上述源码检查不同，会实际启动
Chromium，**此处没有执行**，不能在当前禁止浏览器启动的环境运行。只有在另行
获得允许的环境才能使用：

```bash
npm run validate:gallery -- --allow-browser --out validation/gallery
# 可选：--browser /absolute/path/to/chromium --timeout 15000
```

必须明确传入 `--allow-browser`，缺少时在任何浏览器启动之前拒绝。
该参数只是防误触门槛，不是绕过环境或用户授权的方式。脚本不自动安装浏览器，
不使用 no-sandbox / disable-web-security，不改变卡片或图库 CSP，不触发 Actions。
输出目录必须为空或不存在，不覆盖已有验收证据。

脚本从真实 file:// 页面检查：

- 当前静态索引先通过构建一致性 / 证据检查，再启动允许的本地 Chromium。
- 本地 CSS 的计算样式、本地经典 JS 初始化、全部原始 PNG 的加载与真实尺寸、
  精确 CSP，以及控制台、脚本、资源和 CSP 错误。页面请求只允许索引、图库 CSS / JS
  和已验收 PNG 的精确本地 URL；其他请求被阻止并计为失败。此处检查页面请求，
  不宣称已监测浏览器进程所有后台流量。
- 逐项家族 / 图片需求 / 密度筛选，关键词规范化、空结果、组合、重复筛选和重置；
  数量取自当前注册表，不锁定 24 或 48。
- 原生 label 关联、Tab / Shift+Tab 顺序、可见焦点、跳过链接和 details 键盘切换。
- JS 被禁用的独立上下文中，所有目录、输入链接、真实图像与原生详情仍可使用。
- 1280px 桌面、375 / 390px 手机视口，以及 1280×900 桌面的 200% 等效重排视口
  640×450；折叠和展开全部详情后检查页面与后代元素的横向溢出。

200% 检查采用缩小 CSS 视口的等效重排法，**不是实际浏览器菜单缩放，也不是
不改变布局的 pinch zoom**。报告明确记录方法，实际浏览器 UI 的 200% 缩放仍待
单独检查；不通过修改字体、样式或 CSP 让测试“通过”。

每个视口保存索引、真实预览区域、候选目录起始处与首个展开详情的视口截图；
另有禁用 JS 的目录截图。截图不是整页，也不宣称包含每个条目的每个像素。
`summary.json` 汇总独立检查的成功 / 失败、页面请求与错误、浏览器版本、输入与
验证脚本 SHA-256、截图大小 / SHA-256 / 视口 / 范围及清理结果。
一个几何失败不会跳过其他视口与无脚本检查；启动失败不重试，退出非零，保留报告。

源码/mock 测试验证参数门槛、精确本地请求白名单、派生筛选数、失败聚合、超时、
输出保护、浏览器清理和启动失败路径，不替代以上真实执行。通过真实脚本后仍需
**独立视觉复核**；自动焦点 / 标签检查也不等于读屏或完整可访问性认证。
屏幕阅读器播报、对比度、独立视觉质量、实际菜单缩放及不同浏览器的兼容性仍另行记录。

浏览器检查对全部 page/locator evaluate、evaluateAll（包括 image.decode Promise）单独设置 15 秒上限，不假定 Playwright 默认动作超时会覆盖求值。停滞时记录失败并走 context/browser 清理；源码替身回归覆盖这一故障。

画幅支持单独读取注册表并显示为源码契约，不计为额外模板或额外预览。验收匹配具体画幅的 aspectLayouts 记录，不能把已验收的 portrait PNG 用于 square/slide；当前只有四套默认 portrait 的证据绑定。
