## 必须一起阅读的限制

- T34 的浮动首字造成原生 PDF 的 raw 文本抽取顺序非连续。视觉、字词保全通过，但不承诺该装饰版式整段复制或逻辑顺序搜索可靠。
- 历史截图是实际卡片截图，不是产品 UI 截图，更不是当前模板验收证据。缩小后图片内部微字不可读，应查看原图；外部标题、说明和来源须保持可读。
- 图库通过的是 Chromium 的实际 file:// 页面和 640×450 CSS 视口的等效 200% reflow。未执行原生浏览器菜单缩放、辅助技术屏幕阅读器或跨浏览器认证。
- T36 的链接标签在当前窄区换行，是保全完整文字的非阻塞表现；T40 小号图内编号在简单 1/2 映射中可辨，不是复杂标注可读性保证。
- 三档密度、短/中/长输入、图片类型与画幅是有界的针对性矩阵，不是 48 套的任意组合覆盖。

## 不变的保全与安全边界

默认 `manual`；`auto` 仍仅支持 `explainer` / `steps` 和 `layout` 元数据。`===` 锁定，`--balance-tail` 必须显式开启。不改写原文、删出处/单位/限定条件、拆原子块、缩字、裁切文字或隐藏溢出；不自动增加封面、总结或 CTA。

图片继续使用可信本地 raster resolver、原比例完整显示与既有资源/像素/输出预算。模板不能插入任意 CSS/HTML/路径或偷改原始列表编号。演示数据、原创素材、合成人像与真实引用分别注明来源；没有新增账号、同步、模型调用、部署或 PPTX。

## 复核与复现入口

源码检查：`npm run test:unit`、`npm run gallery:check`。真实验证使用获准环境中的现有套件：`validate:tail`、`validate:templates`、`validate:series`、`validate:visual-stress`、`validate:gallery`、`validate:aspects`，以及旧 showcase 和语义分页回归。`--plan`、mock DOM 和源测试不启动浏览器，也不是视觉证据。

每次发布须将验收文档、注册状态、证据绑定、真实预览和可复现输入同时对齐。源代码、机器 gate、独立视觉结论各自保留，失败不改成跳过，历史 M1 记录不被追写为新的全库结论。各套件摘要与产物哈希见 [验证来源摘要](upgrade-validation-provenance.json)，48 套和新增画幅分别见 [模板来源](template-upgrade-provenance.json) 与 [画幅来源](aspect-upgrade-provenance.json)。
