# 视觉升级与成品模板库执行计划

更新日期：2026-10-24。本文把《MD2Card 视觉对比与模板库待完善清单》的 LIB、VIS、QA 任务落实到可独立审阅的里程碑，不替代 [现有开发与验收记录](DEVELOPMENT_PLAN.md)，并遵守 [Skill 使用规则](../SKILL.md) 与 [渲染契约](../references/rendering.md)。

## 1. 目标、现状与边界

主线是增加真正好看、可以直接选用的成品模板，排版引擎改进服务于模板设计。建设目标分为：先覆盖 12 个风格家族的 24 套精选模板，再补齐 48 套独立构图。**这两个数字是目标，不是当前完成数量。** 配色、品牌、字体或画幅变体不单独计数；与已有模板构图等价的候选必须合并或重做。

现有五主题、八种语义版式、资源安全、真实导出和受限自动分页可以复用，但不等于本轮模板已经实现或通过视觉验收。历史截图和历史 CI 只证明其对应代码、输入与环境。本文建立执行顺序和验收门槛；没有附本轮精确产物及复核记录的条目，状态一律是计划中或待验收，不得据此宣称完成。

当前进度：M1 的 T01/T05/T17/T25 已完成默认 3:4 示例验收，累计 **4/24、4/48**；其他条目仍是规划或待验收，未列入成品数量。精确提交、真实预览与限制见 [模板验收记录](TEMPLATE_ACCEPTANCE.md)。M2 的六套构图已实现、等待真实渲染与视觉验收；加上 M3–M7 的实现，源码候选共 48 套、覆盖 12 个家族，已验收成品仍为 4 套。详见 [M2 候选与验证边界](TEMPLATE_M2.md) 、[M3 候选记录](TEMPLATE_M3.md) 、[M4 候选记录](TEMPLATE_M4.md) 、[M5 候选记录](TEMPLATE_M5.md) 、[M6 候选记录](TEMPLATE_M6.md) 与 [M7 候选记录](TEMPLATE_M7.md)。

### 不可回退的现有契约

- 默认仍是 `--paginate manual`，保留显式卡片数量与内容；自动分页必须主动选择。没有模板选项的旧调用保持原行为。
- `auto` 仍只支持 `explainer`、`steps`，卡片元数据仍只允许 `layout`。新增成品模板不顺带扩大自动分页语义，不删除出处等字段来绕过拒绝。
- `===` 是锁定边界。原文、顺序、段落、引用、代码、图片和顶层列表项的原子性保留；表格只能按完整行拆分，重复表头要有来源记录。
- 不通过自动改写、无提示缩字、删出处、填充废话、裁切文字或隐藏溢出来适配模板。超出能力时给出可定位错误、合适模板建议或需用户授权的编辑建议。
- 主题语言、语义结构与成品模板保持分层。模板可以组合受控组件，但不能注入任意 HTML/CSS、扩大资源根目录或绕过安全检查。
- 图片默认保全内容与比例；裁切、焦点或遮罩只能通过明确、受验证的选项选择。保留本地静态 PNG/JPEG/WebP、安全路径和资源预算约束。
- 不做账号、云同步、在线协作平台、内置 AI/模型调用、自动发布或 PPTX。可以借鉴公开视觉原则，不复制 AGPL 项目的代码、模板、样式或受保护品牌资产；本项目独立实现，字体和素材许可必须可追踪。

## 2. 单套成品模板的交付契约（LIB-02）

注册表应是机器可验证的唯一入口，文档、CLI/Skill 选择与图库从同一份契约读取，避免三个互相漂移的列表。契约的准确字段名随实现提交确认，下列信息必须覆盖：

1. 稳定 ID（T01–T48）、名称、家族、具体用途、设计摘要、版本与验收状态。
2. 使用的主题语言、语义结构、受控构图组件与支持的分页模式。旧命令不受影响，未知 ID、非法组合和不支持的模式明确拒绝。
3. 适用与不适用内容，必需/可选图片、图片比例建议，推荐内容量及已验证的短/中/长输入边界。字符数只是引导，不作为几何成功证明。
4. 支持画幅、标题优先或正文优先、独立的阅读预设与密度预设、标题/正文/来源字阶、间距和网格规则。
5. 示例输入与复现命令，真实 PNG、手机预览、PDF 和 manifest 的来源；记录精确提交、输入/素材/产物哈希与版本。
6. 字体、照片、插画、纹理、图标的来源及许可；原创素材说明。示例数据标明虚构，引用与证据保留真实出处，缺少素材不能由未经授权的远程下载补足。
7. 输入不满足模板需要或容量超限时的明确行为。不得空造指标、引用、人物或“研究结论”，也不得悄悄换成别的模板。

只有以上交付包和本章后续质量门槛均满足，才把模板状态改为“已验收”。注册表条目、CSS 名称、静态草图和尚未检查的导出都不是成品模板。

## 3. 手机阅读与构图基线（VIS-01、VIS-02、VIS-03）

### 手机验收必须看实际卡片显示宽度

- 检查 375px 和 390px 两个 CSS 视口。当前预览若每侧留 12px，卡片实际宽度分别为 **351px / 366px**，不能把视口宽度当作卡片宽度计算字阶。若预览结构变更，重新测量真实宽度并记录，而不是沿用假设。
- 记录导出画布、卡片实际显示宽度、缩放比与计算样式。对 1080px 宽画布，有效字级 = 最终计算字级 × 实际卡宽 / 1080；例如 44px 正文在上述两种卡宽下约为 14.3px / 14.9px。此处仅为规划示例，不是已验证结果。
- mobile 阅读预设的正文目标约 **14–16px**，必要图注/出处目标约 **11–12px**。表格说明、列表与代码中承担正文含义的文字不能藏进小号图注档；标题、页码和装饰字单独规定用途。
- 字级用最终计算结果检查，包括表格、引用、代码和嵌套列表，防止多层 `em` 累乘缩小。高分辨率 PNG、设备 DPR 或放大后清楚都不能替代自然手机尺寸可读。
- 两种手机宽度均需查看实际图像/预览；确认中英文、数字、标点、深色对比、来源与长链接无裁切、缺字、过密和重叠。不能只用几何无溢出或 CSS 快照代替视觉判断。

### 阅读预设与密度独立

`mobile` 表示阅读距离和字阶目标；`compact / standard / editorial` 表示间距、分区和构图节奏，不是一组偷偷变小的字体。标题优先适合封面/宣言，正文优先适合解释/教程，不能靠题头持续膨胀挤压正文。短内容允许有意留白，但要有明确焦点；长内容必须保留原文，不以统一填满或随意缩字过关。

连续主标题应形成一个视觉组，可有主副标题层次，但不重复添加互相竞争的底线。局部高亮、结论框、编号条和来源区采用受控组件与克制/标准/强强调档，不把全文加粗当作强调系统。

## 4. 12 个家族的差异化设计规则（VIS-07）

每个家族在首个模板引入时定义字阶、线条、背景、组件、留白规则，并复用阅读基线；不等到最后一次性换皮。

| 家族 | 必须体现的设计语言 | 与其他家族的边界及禁区 |
| --- | --- | --- |
| 科学 / 编辑杂志 | 衬线主标题、精确网格、侧栏导读、编号图注、证据出处 | 用信息层级组织而不是只换宋体；区别于报刊的密集栏线与报头 |
| 瑞士极简 | 非对称网格、大数字导航、强字号对比、对齐与明确读序 | 大字应负责索引，不挤压正文；不能退化成居中标题加空白 |
| 包豪斯几何 | 圆/方/色块作为信息分组、节点与分区，网格控制节奏 | 几何形状必须参与组织；不随机铺圆形、不让装饰盖住文字 |
| 新粗野海报 | 强字体、粗边框、硬边区域、票据式行动信息 | 大标题可有冲击但正文不可缩小；区别于波普的气泡和叙事 |
| 深色科技 | 深底高对比、等宽标签、层级编号、受控荧光强调 | 正文与代码各自可读；不能整段荧光、伪造终端输出或架构关系 |
| 数据与商业 | 数字、单位、时间、证据、限定条件依层级组织 | 指标与来源始终成组；缺数据保留缺口，不编造业绩或图表 |
| 温暖手账 | 柔和纸感、便签、批注轨、标签与可读书写节奏 | 纹理避让标题；区别于自然生活的照片/材料主导构图 |
| 东方书卷 | 宋体字阶、题签、朱印式标记、横排诗文与留白 | 不擅改断句、不强制竖排、不用假署名和虚构古典引文 |
| 复古报刊 | 报头、栏线、资料标签、侧注与专栏阅读路线 | 报刊不是杂志换色；多栏须在手机尺度仍清楚，不以极细小字仿旧 |
| 胶片摄影 | 照片主导、信息带、接触印样、受控侧栏叙述 | 人脸、主体和截图不能默认裁切；文字区必须有安全对比 |
| 糖果波普 | 大色块、局部高亮、问答气泡、步骤贴纸与分镜 | 视觉活泼但读序稳定；贴纸不能遮挡正文，气泡不能迫使缩字 |
| 自然生活 | 柔色、自然材料层次、照片/原创插画、呼吸感 | 来源可追踪；不同于便签手账，不套用医疗/功效承诺填充示例 |

## 5. 里程碑与依赖

顺序为 M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8 → M9。前一批的契约、回归和源码审查稳定后，下一批可在其分支上以草稿 PR 继续；前一批视觉阻塞必须明确列出，不能沿用未经验证的结论。

模板需要的图片、表格、代码或标题组件可以提前落在对应批次，只实现该批设计确实需要的最小能力，并带测试。M8 负责剩余能力与跨模板收敛，不是让 M1–M7 的已知缺陷积压到最后。基础真实预览随每批模板同步提供，M9 才完成统一筛选图库与多画幅交付。

## 7. 必须执行的审查与测试闭环（QA-01、QA-02）

### 测试语料与证据矩阵

- 固定同一短文、同一 3:4 画布比较多个适配模板；比较中不得为了某模板更漂亮而删改原文。模板确实不兼容输入时明确标记，不硬塞。
- 每个模板另提供自然匹配其用途的样例，以及短/中/长压力输入。字数范围由真实测量确定，不能用超短宣传稿冒充普通内容覆盖。
- 共用压力集包含：长中英文标题、中英混排、数字/标点、长 URL、段落、引用/出处、列表/嵌套项、表格、代码和不同图片比例。每项标明适用模板，避免把不支持功能写成验证成功。
- 每次样式/构图更改保存同输入的前后真实产物；人工判断焦点、字阶、密度、裁切和读序，像素差异仅帮助发现变化，不作为审美结论。

### 四道相互独立的质量门槛

1. **源码审查：**逐项检查参数/注册表校验、默认值和优先级、主题/版式/模板边界、样式作用域、来源保全、资源安全、错误路径、文档一致性。对生成器还要审查 HTML/路径转义、索引与产物匹配。审查必须指出发现、修复和剩余限制，不以“CI 已绿”替代。
2. **本地单元与故障测试：**运行适用的非浏览器测试，覆盖合法与非法 ID、组合、模式、资源、超长标题、原子块溢出、预算与清理、已有 manual/auto 行为。可控测量/假浏览器只能证明算法与生命周期，不能证明真实排版。
3. **真实浏览器与导出：**在被允许的执行环境，对精确提交运行真实 Chromium 的 screen/print 测量，收集完整 PNG、手机预览、原生可检索 PDF、联系表与 manifest。核对页数、文本、图片解码、字体、来源覆盖和哈希。记录实际通过/失败/跳过情况，不把跳过写成通过。
4. **产物视觉与内容复核：**每套新增模板的所有示例页面都要检查原尺寸和两种手机宽度；PDF 单独确认页面边界、可选文本与关键内容。核对正文、单位、时间、出处和限制未丢失/错配；复查深色、长表、长代码、人像和截图。联系表适合看节奏，但不能代替单页检查。

若发现问题，修复后重新运行受影响测试、导出和视觉检查；不可拿修复前的截图或别的提交的 CI 结果为新代码背书。若完整 Git 树与被测提交一致，可记录树哈希关系，但必须说明，不隐去来源。

### 本地浏览器受限时的处理

当前项目记录了本地 Chromium 被沙箱拒绝的限制。不得重试同一被拒绝的浏览器操作、换启动参数或换路径绕过限制。继续可执行的源码审查、单元测试与故障测试；在仓库原有、获允许的 CI 中收集真实 PNG/PDF，再下载检查实际产物，是合法的验证分工，不等于依赖 CI 替代审查。

浏览器或产物不可取得时，必须写明“真实导出待验证”或“视觉待验收”，不能将模板标成已验收。不得用 HTML 静态结构、手绘/生成的概念图或历史图片补写本轮验证结果。浏览器限制不阻止文档、设计契约和非浏览器测试推进，但阻止相关视觉完成声明。

### 每批验收记录模板

每个里程碑在 PR 与对应验收记录中追加以下信息，不预填成功：

- 精确代码提交/树、基准分支、模板 ID、输入和运行命令。
- 实现范围与仍未支持的组合；独立源码审查发现及修复提交。
- 本地单元/故障测试结果，真实浏览器执行位置，CI 链接和明确的跳过/受限项。
- 真实 PNG/PDF/预览/manifest 的来源与哈希，已检查页面和手机宽度；视觉发现与修复前后证据。
- 内容、来源、单位与限定条件复核；素材来源/许可与示例数据标注。
- 实现、单测、真实导出、视觉、文档展示分别记状态；有未完成门槛就保留待验收，不以一个总“完成”掩盖差异。

## 8. 中等大小草稿 PR 的实施方式

PR 按可审阅的用户能力组织，不按文件类型拆成无法运行的碎片，也不把 48 套与引擎一起塞进一个 PR。所有本轮 PR 均先创建为 **Draft，保持堆叠，不自行合并**；当前 PR 依赖未合并 PR 时，将基准明确指向上一个分支并说明依赖链。

建议拆分：

- M1a：注册表、模板选择/校验、mobile 与密度底座、兼容/故障测试；M1b：T01/T05/T17/T25、真实样例、导出与视觉证据。若变更量仍适中且审阅主题一致，可合为一个 M1 PR。
- M2、M3：各自按两到三个家族划分，组件与第一批使用它的模板同 PR；不要提前加入后续全部泛化接口。
- M4：报刊/摄影与波普/生活分组，图片底座只覆盖本批实际需要。
- M5–M7：各里程碑按两个家族一组推进，每组附完整样例和验收；如共享组件导致差异膨胀，先单独提交小底座 PR，再堆叠设计 PR。
- M8：密度/标题/历史样例、图文/表格/代码、尾页平衡分别审阅；尾页算法不能夹在样式批量修改中。
- M9：筛选图库、系列配方、独立画幅分别审阅，并说明哪些模板/画幅已经真实验证。

“中等大小”以审阅者能理解一个主题、复现改动并核对全部新模板为准，不以固定行数凑范围。生成 PNG 可以使二进制差异较大，应与源代码改动分别报告；当一个 PR 同时改变复杂算法和多个无关家族时必须拆分。

每个 PR 的固定步骤：明确范围与依赖 → 实现最小能力和样例 → 自审及独立源码复核 → 单元/故障测试 → 在允许环境真实导出 → 检查所有新增示例页并修复 → 更新精确证据与限制 → 创建/更新草稿 PR。发现缺陷后留在原主题内修复，跨主题问题登记到对应里程碑；不能因为 CI 全绿直接进入合并或宣称美术验收。

## 9. 完成定义与后续取舍

模板库达到阶段目标的条件，是指定集合中的每个设计都满足交付契约、独立构图、真实内容适配、来源许可和四道质量门槛。注册条目数量不代表完成数量；未验收设计可以保留为候选，但图库不得暗示其已经可用。

优先顺序始终是：内容和安全保真 → 自然手机阅读 → 成品构图质量 → 覆盖更多真实用途 → 检索和其他画幅。为了达到模板数量而牺牲前面任何一项都不合格。遇到能力边界，优先缩小单次 PR 的范围、明确不支持情况，并继续可独立完成的工作，而不是虚报完成或放松既有契约。
