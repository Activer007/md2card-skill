# ADR-001：先冻结证据，再增量实现

日期：2026-10-25。状态：M0 范围决策已记录；未来接口仍待各阶段具体设计与审查。依据：外部开发包 C01–C10、当前 main 源码和本次 [基线证据](BASELINE-EVIDENCE.md)。

## 采纳的边界

| 原则 | 决策与原因 |
| --- | --- |
| C01 原文保真 | 保留源文、顺序、数字、来源和限定语；PDF 比对以原始输入片段为准，不从产物倒推期望值。T05 提取顺序保留为发现 |
| C02 默认兼容 | 新功能必须 opt-in；当前 manual/medium/legacy、模板默认 PNG/HTML/PDF 不应受影响。不得自动更新快照消除差异 |
| C03 禁任意注入 | 不接受用户 HTML/CSS/JS 或远程资源；字段采用有限枚举和白名单，拒绝任意 style 对象 |
| C04 本地图像安全 | 复用可信 asset root、realpath、MIME/解码/资源预算；推荐器不能偷偷下载图片 |
| C05 图像完整性 | 默认 contain；裁切需要明确变体和授权语义，保留图像身份。T20 不允许为美观丢失截图内容 |
| C06 有界资源 | 沿用尺寸、卡数、字节/像素和超时预算；禁止无界反复渲染测量推荐 |
| C07 原生 PDF | 保留文字层及来源；完整工具环境下验证原文和编号。当前独立提取证据不能替代缺失的官方门槛 |
| C08 证据不迁移 | 每个新变体绑定自己的输入、样式、环境和 PNG/mobile/PDF；旧图库证据不可继承为新验收 |
| C09 硬失败 | CONTENT_OVERFLOW、安全和不支持契约维持失败；视觉建议独立呈现，不降级成警告 |
| C10 有限画幅 | 支持矩阵显式按模板注册；不得把少数实现宣传为全库支持 |

不采纳直接复制 Guizang 的 HTML/CSS/素材/字体、让模型自由生成布局、默认替换旧构图、为了手机字大而改写文章或裁掉图片的方案。本次素材全部沿用项目已有原创/合成输入，并保留虚构产品、AI 图像等说明。

## 后续顺序和安全入口

建议顺序：**先补齐严格验收环境及 PDF 差异复核 → M1 → M2a → M2b → M3 → M4**。M1 的纯只读实现可以在环境补齐期间独立推进；任何新的视觉验收通过声明必须等严格门槛恢复。该顺序是后续任务建议，本次没有启动实现。

1. **环境 / PDF 基线收口**：在具有真实 Fontconfig、Poppler 的受控环境复跑本次原始输入和 unit/integration。固定 Chrome/字体版本，核对 T05 列表提取顺序及变量字体兼容字符。记录不同提取器结果；先确认原因，再单独修复或记录支持范围，不能把 NFC 改成 NFKC 来掩盖差异。
2. **M1，P11–P14：只读选型**。先新增纯函数内容角色摘要，复用 Markdown token/已有元数据和真实图片验证结果；不确定返回 unknown。再基于 48 模板现有能力表做硬条件排除、稳定排序、最多 3 个候选和拒绝理由，最后接独立 CLI/文档。输入不改写，不启动卡片导出，不改变 render 默认路径；推荐不承诺一定容纳内容。建议一个独立 PR，以默认兼容、未知输入和拒绝行为为门槛。
3. **M2a，I21–I23：T20 screenshot-stage**。先设计模板专属有限字段、未知值/错误模板/自动分页拒绝矩阵，再实现 opt-in 构图，最后用相同原图、短中长文本和宽高比压力样例复核。`visualVariant: screenshot-stage` 只是拟议名称，当前仍 INVALID_METADATA；不得提前放宽公共 parser。验收须同时展示旧默认与新变体的 PNG、375/390 和原生 PDF；图片微字必须给出可测的适用范围，不承诺位图文字自动变清晰。建议与 M1 分开 PR。
4. **M2b，I24–I27**：T37 照片封面是独立任务；先写适用性、主体保护、裁切许可和回退规则，再做满铺叠字。现有 AI 静物图不能代表复杂人像/主体边缘等压力案例。
5. **M3，Q31–Q35**：复用已有 DOM 几何测量，提供可选诊断和反例；不重新建立第二套溢出判定，不让建议覆盖硬失败。
6. **M4，X41–X44**：21:9、T01/T21 特定组合和双输入封面对输出最后立项；单独注册/验收，不能直接拉伸 portrait。

## M0 建议 PR 和发布边界

标题建议：`docs: freeze visual-upgrade M0 baseline and rejection fixtures`。

仅纳入 4 份本文档、1 份 provenance JSON、1 份案例 JSON、2 份拒绝 Markdown，以及 `docs/evidence/visual-upgrade-m0-70383b8.zip` 原始证据包。现有 renderer、解析器、样式、原始样例、SKILL.md、package.json 和图库都不改。保留证据 ZIP 的 SHA-256，说明 B01/B02 的保留项；不复制完整外部规划包，不打包本地字体或安装副本。

提交前核对 runtime diff 为零、provenance 全部哈希可解析、证据包含原始输入/图像/实际产物/脚本/日志。PR 的“完成基线采集”不等于“所有严格门槛通过”。后续 PR 必须引用此 ADR，并说明新增验收范围。维护者已授权发布顺序为：先提交、审查修复并合并 M0，再合并 M1-A。

发布审查补充：后续 M1 已拆分为 M1-A 纯函数摘要/推荐（PR #25）与 M1-B CLI/图库接入；上文单 PR 的建议属于采集时规划，本次按该拆分推进。严格环境门槛和视觉验收边界不变。
