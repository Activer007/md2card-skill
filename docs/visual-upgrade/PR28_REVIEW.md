## 发现与修复

1. **P2：验收脚本把 README 当作输入。** 原逻辑枚举全部 `.md`，新增 README 后无法重现完整验收。改为核对显式的 14 个样例清单，只排除 README；缺失或额外样例要求明确审查，不能悄悄少跑案例。
2. **P2：重复运行可能覆盖旧证据。** 原脚本在确认输出目录状态前写入输入文件和进度。改为在浏览器启动、证据写入之前拒绝非空目录和符号链接；仓库内只能输出到 `validation/`。回归测试验证原输入与进度文件字节保持不变。
3. **P2：字符串替换可能未关闭新模式。** 元数据空格或键顺序变化时，默认/新模式对照可能都启用 screenshot-stage。改为解析 JSON、验证模式并只移除 `visualVariant`；正文和元数据字面值（包括 `$&`）不改写。
4. **P2：历史基线身份不充分。** 原脚本把任意 baseline-root 标为固定 main，并用当前解析器/样式构造一部分旧输出。现先将基线语义文件逐一对照固定 Git commit 的 SHA-256，再加载旧解析器和旧样式。未提供基线时，报告明确记录 null，不声称已完成历史对照。

这些修改限于 `scripts/validate-screenshot-stage.mjs` 和测试。解析器、渲染器、模板 CSS、默认兼容性证明及历史 ZIP 均未改动。原始 ZIP 和清单内每个文件的 SHA-256 已复核；全部实际渲染源码仍与旧视觉证据一致。
