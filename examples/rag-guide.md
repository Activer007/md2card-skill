# RAG：先找依据，再给答案

**AI 知识卡 · 从概念到验证**

当问题依赖特定资料时，不必让模型只凭训练时的记忆回答。RAG 把“查找资料”和“组织答案”连接起来。

## 一个容易理解的比喻

把模型想成写作者，把检索系统想成资料员：资料员先找到相关段落，写作者再结合这些内容回答问题。

- **检索**：从指定资料库中寻找相关内容。
- **增强**：把找到的片段放入本次输入。
- **生成**：根据问题和这些片段组织答案。

> 关键不是“多给一些文字”，而是给出相关、可靠且允许使用的证据。

===

# 一次回答，经过哪些步骤？

**从用户问题，到可核对的依据**

1. **整理资料**：把文档拆成适合检索的片段，保留标题、出处和必要的上下文。
2. **寻找候选**：使用关键词、向量相似度或组合方法，召回可能相关的内容。
3. **筛选证据**：剔除不相关或无权访问的片段，必要时重新排序。
4. **组织回答**：让模型围绕证据作答，并给读者提供核对来源的路径。

## 最小流程示意

```text
问题 → 检索 → 相关片段
              ↓
       问题 + 证据 → 回答
```

这是概念流程，不是可直接部署的完整系统。具体实现还需要权限、更新和失败处理。

===

# 有检索，不等于一定正确

**把检索质量与回答质量分开看**

| 检查对象 | 要问的问题 |
| --- | --- |
| 资料 | 内容是否可信、适用且足够新？ |
| 检索 | 真正需要的证据是否被找到？ |
| 回答 | 每个关键结论是否有证据支撑？ |

## 三种常见失误

- **找错**：相似词很多，但场景并不相同。
- **漏找**：关键条件不在被召回的片段里。
- **说过头**：证据只支持局部结论，回答却做了扩大解释。

> 没有充分依据时，应说明信息不足，而不是补出一个看似完整的答案。

===

# 从一个小测试集开始

**先知道哪里失效，再决定怎么优化**

选一组真实、可核对的问题，记录理想答案依赖哪些资料。测试集应包含“有答案”和“资料不足”的情况。

## 每次改动后，重新检查

1. 正确资料是否进入候选结果？
2. 回答是否忠实于检索到的证据？
3. 引用是否真的支持对应的结论？
4. 信息不足时，系统是否表达了限制？

不要只看演示是否流畅。把失败样例留下来，比单次漂亮回答更有助于改进系统。
